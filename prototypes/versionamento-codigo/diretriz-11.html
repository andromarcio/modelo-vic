11
Diretriz

Repositórios, branches e versões devem apresentar padrões de nomenclatura

Regra

A nomenclatura dos principais elementos do versionamento deve ser padronizada, facilitando identificação, controle de acesso e geração de indicadores. Cada elemento deve estar aderente ao padrão esperado.

Padrões por elemento

ElementoPadrão obrigatórioReferência
RepositóriosSISTEMA-moduloAderente ao cadastro de item de portfólio
Branches Permanentes: main, develop
Temporárias: feature/*, release/*, hotfix/*		 Aderente ao GitFlow ou GitHub Flow (ver Diretriz 2)
Versões MAJOR.MINOR.PATCH
MAJOR.MINOR.PATCH.BUILD — obrigatório em produção		 Aderente ao SemVer (ver Diretriz 9) e ao Padrão VEC (ver Diretriz 10)

A verificação de aderência desses padrões deve ser contínua, pois sustenta o controle de acesso e a geração de indicadores de governança.

Como verificar a aderência

A verificação é de formato. A existência da sigla não precisa ser validada pela coleta: repositórios são criados exclusivamente para siglas já cadastradas, de modo que a origem da sigla é garantida no ato da criação.

ElementoExpressão regular de conformidade
Repositórios ^[A-Z][A-Z0-9]{1,9}-[a-z0-9]+(-[a-z0-9]+)*$
Branches ^(main|develop|(feature|release|hotfix)/[a-z0-9][a-z0-9._-]*)$
Versões ^v?[0-9]+\.[0-9]+\.[0-9]+(\.[0-9]+)?$
Coleta Apuração das não conformidades
# Repositórios fora do padrão
gh api "orgs/$ORG/repos" --paginate --jq '.[]
  | select(.name | test("^[A-Z][A-Z0-9]{1,9}-[a-z0-9]+(-[a-z0-9]+)*$") | not)
  | .name'

# Branches fora do padrão
gh api "repos/$ORG/$REPO/branches" --paginate --jq '.[]
  | select(.name | test("^(main|develop|(feature|release|hotfix)/[a-z0-9][a-z0-9._-]*)$") | not)
  | .name'

# Tags fora do padrão
gh api "repos/$ORG/$REPO/tags" --paginate --jq '.[]
  | select(.name | test("^v?[0-9]+\\.[0-9]+\\.[0-9]+(\\.[0-9]+)?$") | not)
  | .name'

Condições de contorno da apuração

  • Em repositórios que adotam GitHub Flow, a ausência de develop não é não conformidade — a Diretriz 2 admite os dois modelos. A apuração deve considerar o modelo adotado pelo repositório antes de exigir a branch.
  • A expressão de repositório rejeita _ e ., que o GitHub aceita em nomes. A rejeição é intencional: o padrão institucional prevê apenas o hífen como separador.
  • A expressão de versões admite o prefixo v por ser convenção corrente no Git e constar do exemplo da Diretriz 13. A obrigatoriedade ou a vedação do prefixo deve ser definida pela governança técnica e refletida na expressão.
