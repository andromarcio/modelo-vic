Diretriz

O modelo de flow adotado deve ser aderente ao GitFlow ou GitHub Flow

Regra

O modelo de fluxo de trabalho adotado pela equipe de desenvolvimento deve ser aderente aos modelos de mercado GitFlow ou GitHub Flow. Os repositórios devem manter as branches develop e/ou main presentes, protegidas e atualizadas.

O que a diretriz exige

O fluxo de trabalho deve estar alinhado a um padrão consolidado de mercado. Independentemente de adaptações, os requisitos a seguir são de cumprimento obrigatório:

  • O repositório deve adotar GitFlow ou GitHub Flow como modelo de fluxo.
  • As branches develop e/ou main devem estar presentes e protegidas.
  • As branches principais devem ser mantidas atualizadas, com integração contínua de código.
  • O modelo adotado deve estar em conformidade com a governança técnica institucional.

GitFlow × GitHub Flow

Os dois modelos são aderentes ao padrão de mercado. A diferença central está no número de branches permanentes e na forma de versionar entregas.

AspectoGitFlowGitHub Flow
Branches permanentesmain e developapenas main
Branches de suportefeature/*, release/*, hotfix/*feature/* (curtas)
Versionamentorelease versionada (tag SemVer) + merge backdeploy contínuo a partir da main

Modelo de referência do capítulo

As diretrizes 3, 4 e 5 detalham mecânicas do GitFlow (branches de release/hotfix e merge back). Em repositórios que adotam GitHub Flow, aplica-se a equivalência sobre a única branch permanente (main).
